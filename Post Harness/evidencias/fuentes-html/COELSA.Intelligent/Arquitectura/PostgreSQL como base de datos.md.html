0009
0010 # PostgreSQL como base de datos
0011
0012 ## Qué es
0013
0014 El upstream Open WebUI usa SQLite por defecto. COELSA.Intelligent **migró a PostgreSQL** para soportar múltiples workers concurrentes, backups corporativos y el modelo de despliegue en [[OpenShift]].
0015
0016 ## Configuración
0017
0018 ```env
0019 DATABASE_URL=postgresql://user:pass@host:5432/coelsa_intelligent
0020 ```
0021
0022 El esquema se gestiona con **Alembic**. Las migraciones están en `backend/server/migrations/`. El servidor ejecuta `alembic upgrade head` automáticamente al arrancar (via `run_migrations()` en `config.py`).
0023
0024 ## Por qué PostgreSQL
0025
0026 - SQLite no admite múltiples writers concurrentes; con uvicorn en múltiples workers genera errores de lock.
0027 - PostgreSQL tiene soporte corporativo, backup integrado con las herramientas de COELSA, y funcionalidades como JSON columns (usadas en varios modelos).
0028 - La versión mínima requerida es **14+** por el uso de `json_agg` y funciones de ventana.
0029
0030 ## Stack de acceso a datos
0031
0032 - **ORM**: SQLAlchemy (con `get_db()` como context manager de sesión)
0033 - **Migraciones**: Alembic (ver [[Migraciones Alembic]])
0034 - **Modelos**: `backend/server/models/` — User, Chat, File, Knowledge, Group, Memory, etc.
