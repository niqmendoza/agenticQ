0010 # Redis para WebSockets
0011
0012 ## Qué es
0013
0014 El servidor de WebSocket de COELSA.Intelligent (implementado con `python-socketio`) usa **Redis como backend de canal**. Esto permite que múltiples instancias del servidor compartan el estado del socket sin pérdida de eventos entre workers.
0015
0016 ## Configuración
0017
0018 ```env
0019 REDIS_URL=redis://host:6379
0020 # O con Redis Sentinel para alta disponibilidad:
0021 REDIS_SENTINEL_HOSTS=sentinel1:26379,sentinel2:26379
0022 REDIS_SENTINEL_PORT=26379
0023 ```
0024
0025 ## Por qué Redis
0026
0027 Sin un backend de canal compartido, cada instancia del servidor tendría su propia cola de eventos. Un mensaje enviado por un cliente conectado al worker A no llegaría a los clientes conectados al worker B. Redis resuelve este problema actuando como bus de mensajes entre instancias.
0028
0029 En [[OpenShift]] el servidor puede escalar horizontalmente (múltiples pods) gracias a este diseño. Sin Redis, el WebSocket funciona solo con un único worker.
0030
0031 ## Configuración de conexión (`config.py`)
0032
0033 La conexión a Redis se obtiene a través de `get_redis_connection()` en `server/utils/redis.py`, que soporta tanto Redis standalone como Redis Sentinel.
