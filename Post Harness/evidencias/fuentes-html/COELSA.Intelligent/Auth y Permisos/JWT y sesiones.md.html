0009
0010 # JWT y sesiones
0011
0012 ## Qué es
0013
0014 Después de un login OAuth exitoso con [[Azure AD OAuth|Azure AD]], COELSA.Intelligent genera un **JWT interno** (JSON Web Token) que el frontend usa en todas las requests subsiguientes. Este token es independiente del token de Azure AD.
0015
0016 ## Especificaciones del token
0017
0018 - **Algoritmo**: HS256 (HMAC con SHA-256)
0019 - **Clave secreta**: `WEBUI_SECRET_KEY` (variable de entorno)
0020 - **Módulo**: `backend/server/utils/auth.py`
0021
0022 ## Generación
0023
0024 ```python
0025 # Pseudocódigo del flujo
0026 token = jwt.encode(
0027 {
0028 "id": user.id,
0029 "email": user.email,
0030 "role": user.role,
0031 "exp": datetime.utcnow() + timedelta(hours=SESSION_HOURS)
0032 },
0033 SESSION_SECRET, # WEBUI_SECRET_KEY
0034 algorithm=ALGORITHM # HS256
0035 )
0036 ```
0037
0038 ## Validación
0039
0040 Cada endpoint protegido valida el token usando el `HTTPBearer` security scheme de FastAPI. El decorador `get_current_user` extrae el usuario del token y verifica que exista en la base de datos.
0041
0042 ## Firma HMAC
0043
0044 Para verificación de webhooks entre servicios internos, existe una firma HMAC separada (`verify_signature()`) usando `TRUSTED_SIGNATURE_KEY`. Usa `hmac.compare_digest` para prevenir timing attacks.
