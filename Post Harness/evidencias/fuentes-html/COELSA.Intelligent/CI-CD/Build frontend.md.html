0010 # Build frontend
0011
0012 ## Qué es
0013
0014 COELSA.Intelligent tiene **dos comandos de build del frontend** con diferencias significativas en cuándo y dónde se usan.
0015
0016 ## Los dos comandos
0017
0018 | Comando | Uso | Incluye Pyodide | RAM necesaria |
0019 |---------|-----|-----------------|--------------|
0020 | `npm run build` | Solo local | ✅ Sí (~500MB adicionales) | 8GB+ sin optimizaciones |
0021 | `npm run build:docker` | CI/CD y Docker | ❌ No | ~4GB con optimizaciones |
0022
0023 **Regla**: en el [[Dockerfile]] y los [[Pipelines Azure DevOps]] siempre usar `npm run build:docker`.
0024
0025 ## Por qué la diferencia
0026
0027 **Pyodide** es el runtime WASM de Python que permite ejecutar Python en el navegador. Su descarga requiere ~500MB de red y puede fallar en entornos con acceso a red restringido (como los agents de CI/CD de COELSA). `build:docker` omite este paso.
0028
0029 ## Optimizaciones automáticas en CI
0030
0031 `vite.config.ts` detecta entornos CI mediante `CI=true`, `TF_BUILD=True` o `DOCKER=true` y aplica automáticamente:
0032
0033 | Optimización | Impacto |
0034 |-------------|---------|
0035 | Sourcemaps deshabilitados | ~50% menos memoria y tiempo |
0036 | Minificación con esbuild (no terser) | ~40% menos memoria |
0037 | `max-old-space-size=4096MB` | Límite de heap Node.js |
0038
0039 ## Volumen del build
0040
0041 El build maneja **más de 4.500 módulos**. Sin las optimizaciones de CI, puede superar **8GB de RAM** y fallar en entornos con límites de memoria.
