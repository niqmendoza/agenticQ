0010 # Dockerfile
0011
0012 ## Qué es
0013
0014 El `Dockerfile` en la raíz del proyecto construye la imagen de producción de COELSA.Intelligent. Combina el build del frontend estático con el backend Python en una sola imagen.
0015
0016 ## Características clave
0017
0018 ### PyTorch CPU-only
0019
0020 ```dockerfile
0021 RUN pip3 install torch==2.5.1+cpu \
0022 --index-url https://download.pytorch.org/whl/cpu
0023 ```
0024
0025 La variante CUDA (~2GB) no se usa porque [[OpenShift]] no tiene GPUs disponibles. Ver [[PyTorch CPU-only]].
0026
0027 ### Sin Pyodide
0028
0029 El build usa `npm run build:docker` (no `npm run build`), que **no descarga Pyodide**. Ver [[Build frontend]].
0030
0031 ### SSL corporativo (riesgo aceptado)
0032
0033 ```dockerfile
0034 ENV NODE_TLS_REJECT_UNAUTHORIZED=0
0035 ENV npm_config_strict_ssl=false
0036 ENV PIP_TRUSTED_HOST="download.pytorch.org pypi.org files.pythonhosted.org"
0037 ```
0038
0039 Estas variables deshabilitan la verificación SSL en `npm` y `pip` durante el build. Necesario en el entorno de CI/CD con proxy corporativo que intercepta HTTPS. Ver [[SSL corporativo en build]] y [[Riesgos de seguridad aceptados]].
0040
0041 ### CHANGELOG en la ruta correcta
0042
0043 ```dockerfile
0044 COPY CHANGELOG.md /app/CHANGELOG.md
0045 ```
0046
0047 Corrección del v1.3.0: anteriormente se copiaba a `/app/backend/CHANGELOG.md` pero la app lo buscaba en `/app/CHANGELOG.md`.
