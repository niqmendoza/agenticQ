0009
0010 # Manejo de errores frontend
0011
0012 ## Qué es
0013
0014 COELSA.Intelligent tiene un sistema de componentes específicos para cada categoría de error HTTP, más un `ErrorBoundary` para capturar errores de renderizado en componentes Svelte.
0015
0016 ## Componentes de error
0017
0018 | Componente | Archivo | Cuándo se muestra |
0019 |-----------|---------|-------------------|
0020 | `NetworkError` | `src/lib/components/error/NetworkError.svelte` | Sin conexión o error de red (0, ECONNREFUSED) |
0021 | `TimeoutError` | `src/lib/components/error/TimeoutError.svelte` | La request excedió el timeout |
0022 | `GenericError` | `src/lib/components/error/GenericError.svelte` | Cualquier error HTTP no categorizado |
0023 | `ErrorBoundary` | `src/lib/components/error/ErrorBoundary.svelte` | Error durante el renderizado de un componente hijo |
0024
0025 ## Routing de errores HTTP
0026
0027 `src/routes/+error.svelte` recibe todos los errores HTTP de SvelteKit y los rutea:
0028 - `0` o sin respuesta → `NetworkError`
0029 - Timeout detectado → `TimeoutError`
0030 - Cualquier otro → `GenericError` (con el código y mensaje del backend)
0031
0032 ## ErrorBoundary (para errores de render)
0033
0034 Envuelve secciones de UI que podrían fallar durante el renderizado:
0035
0036 ```svelte
0037 <ErrorBoundary>
0038 <ComponenteQuePodriaFallar />
0039 </ErrorBoundary>
0040 ```
0041
0042 Si el componente hijo lanza un error durante el render, `ErrorBoundary` lo captura y muestra un fallback en lugar de romper toda la página.
0043
0044 ## Relación con el backend
0045
0046 Los errores del backend llegan con la estructura estándar del [[Sistema de errores centralizado]]:
0047 ```json
0048 { "message": "...", "status_code": 400, "details": "..." }
0049 ```
0050
0051 Los componentes de error extraen el `message` para mostrarlo al usuario.
0052
