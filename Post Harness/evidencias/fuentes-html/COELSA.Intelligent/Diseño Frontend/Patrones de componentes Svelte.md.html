0010 # Patrones de componentes Svelte
0011
0012 ## Qué es
0013
0014 Hay **4 patrones de código en el frontend** que resuelven bugs concretos. Su omisión o reversión reproduce los bugs originales. Documentados aquí como referencia obligatoria al trabajar en `Chat.svelte` y componentes relacionados.
0015
0016 ## 1. Guarda de `chatId` (evita loop de renderizado)
0017
0018 ```typescript
0019 // src/routes/(app)/c/[id]/+page.svelte o Chat.svelte
0020 if ($chatId !== chatIdProp) {
0021 chatId.set(chatIdProp);
0022 }
0023 ```
0024
0025 **Por qué**: sin esta guarda, el cambio de chat dispara una actualización del store que a su vez dispara otro cambio de chat, generando un **loop de renderizado infinito**.
0026
0027 ## 2. `AbortController` en `loadChat` (reduce requests duplicados ~80%)
0028
0029 ```typescript
0030 let currentController: AbortController | null = null;
0031
0032 async function loadChat(id: string) {
0033 currentController?.abort(); // Cancela la carga anterior
0034 currentController = new AbortController();
0035 const data = await fetchChat(id, { signal: currentController.signal });
0036 }
0037 ```
0038
0039 **Por qué**: si el usuario cambia de chat antes de que termine de cargar el anterior, sin `AbortController` ambas requests corren en paralelo y pueden pisarse. Reduce ~80% de requests duplicados.
0040
0041 ## 3. Unsubscribers en `onDestroy` (evita memory leaks)
0042
0043 ```typescript
0044 import { onMount, onDestroy } from 'svelte';
0045
0046 let unsub: () => void;
0047
0048 onMount(() => {
0049 unsub = someStore.subscribe(value => { ... });
0050 });
0051
0052 onDestroy(() => {
0053 unsub?.(); // OBLIGATORIO: limpiar la suscripción
0054 });
0055 ```
0056
0057 **Por qué**: los stores suscritos en `onMount` acumulan listeners si no se destruyen en `onDestroy`. Los listeners fantasma disparan requests adicionales y pueden causar actualizaciones en componentes desmontados.
0058
0059 ## 4. Bloques reactivos unificados (evita ejecuciones duplicadas)
0060
0061 ```typescript
0062 // MAL — separados generan doble ejecución:
0063 $: if (selectedModels) updateModels();
0064 $: if (selectedModels) setToolIds();
0065
0066 // BIEN — unificados:
0067 $: {
0068 if (selectedModels) {
0069 updateModels();
0070 setToolIds();
0071 }
0072 }
0073 ```
0074
0075 **Por qué**: los bloques `$:` separados que dependen del mismo reactive value se ejecutan independientemente. Al unificarlos, solo hay una ejecución por cambio de estado.
