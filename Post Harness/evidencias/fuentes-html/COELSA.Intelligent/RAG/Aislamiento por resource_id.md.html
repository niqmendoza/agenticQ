0009
0010 # Aislamiento por resource_id
0011
0012 ## Qué es
0013
0014 En el esquema de [[Milvus multi-tenancy|multi-tenancy de Milvus]], el aislamiento entre recursos se logra mediante un campo escalar llamado `resource_id` que se almacena junto a cada vector.
0015
0016 ## Cómo funciona
0017
0018 **Al insertar** un vector (chunk de texto):
0019 ```python
0020 # Se incluye resource_id en los metadatos del punto
0021 {
0022 "vector": [0.1, 0.2, ...],
0023 "resource_id": "knowledge-abc123",
0024 "content": "texto del chunk",
0025 "metadata": {...}
0026 }
0027 ```
0028
0029 **Al buscar**:
0030 ```python
0031 # Se aplica un filtro booleano sobre resource_id
0032 search_results = collection.search(
0033 data=[query_embedding],
0034 filter=f'resource_id == "{resource_id}"',
0035 ...
0036 )
0037 ```
0038
0039 Esto garantiza que los resultados de búsqueda pertenecen exclusivamente al recurso solicitado.
0040
0041 ## Por qué es seguro
0042
0043 Milvus ejecuta el filtro booleano en el nivel de cada segmento, antes de devolver resultados. No es posible que un chunk de un `resource_id` diferente aparezca en los resultados de una búsqueda filtrada por otro `resource_id`, siempre que el campo esté indexado correctamente.
0044
0045 ## Cómo se genera el resource_id
0046
0047 El `resource_id` se deriva del identificador del recurso (ID de la Knowledge base, ID del archivo, etc.) mediante una convención de nombres que la función `_get_collection_and_resource_id()` en `milvus_multitenancy.py` implementa.
