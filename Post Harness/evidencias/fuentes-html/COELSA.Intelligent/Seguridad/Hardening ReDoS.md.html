0010 # Hardening ReDoS
0011
0012 ## Qué es
0013
0014 **ReDoS** (Regular Expression Denial of Service) es una vulnerabilidad donde una regex maliciosa o un input especialmente crafteado hace que el motor de regex tarde tiempo exponencial en evaluar. COELSA.Intelligent aplicó **bounded quantifiers** a 11 expresiones regulares que no tenían límites de longitud.
0015
0016 ## El fix: bounded quantifiers
0017
0018 ```python
0019 # ANTES (vulnerable):
0020 re.compile(r'[a-z]+') # Sin límite
0021 re.compile(r'\s*') # Sin límite
0022 re.compile(r'.+?') # Sin límite
0023
0024 # DESPUÉS (con bounds):
0025 re.compile(r'[a-z]{1,50}') # Máximo 50 caracteres
0026 re.compile(r'[ \t]{0,10}') # Máximo 10 espacios
0027 re.compile(r'.{1,500}?') # Máximo 500 caracteres
0028 ```
0029
0030 La regla es: **ningún quantifier sin límite superior** en código que procesa input de usuario.
0031
0032 ## Archivos afectados
0033
0034 - `backend/server/utils/middleware.py`
0035 - `backend/server/utils/misc.py`
0036 - `backend/server/utils/plugin.py`
0037 - Archivos TypeScript del frontend (varios)
0038
0039 **Total**: 11 expresiones regulares en backend (Python) y frontend (TypeScript).
0040
0041 ## Cuándo verificar
0042
0043 Cada vez que se agrega una nueva regex que procesa input de usuario, verificar:
0044 1. ¿Tiene cuantificadores sin límite (`+`, `*`, `{n,}`)?
0045 2. ¿El input puede ser controlado por un usuario no confiable?
0046 3. Si ambas respuestas son sí → agregar bounds explícitos
