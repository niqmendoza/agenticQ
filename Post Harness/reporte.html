## Feature mock: renovar acceso temporal a un archivo desde el chat
Es una extensión propuesta; no afirmar que existe.
P1. Usuario activo solicita renovar acceso de lectura a un File por ID desde el chat. Backend valida identidad y permisos actuales antes de resolver el path; pending no puede usarlo. No aceptar URL/ruta arbitraria del cliente.
P2. Para path S3 emitir acceso firmado al objeto específico. TTL opcional entero en segundos: 60 ≤ TTL ≤ 3600; default 3600. Rechazar fuera de rango, fracciones, booleanos y texto con 422. Son límites y política de validación propuestos, no contratos existentes.
P3. Para path local devolver referencia de descarga del backend protegido; no fingir URL S3 ni prometer expiración S3. No promover el archivo a MinIO desde esta acción.
P4. No alterar ACL, contenido, chat_id ni disparar borrado, limpieza o embeddings; política de last_accessed_at al renovar ABIERTA hasta decisión de producto.
P5. UI con acción explícita, carga y reintento; impedir que una respuesta de otro chat reemplace la actual. Errores sin detalles internos en producción.
P6. Informar que URLs S3 emitidas previamente pueden seguir funcionando hasta expirar aunque se revoque el permiso. No prometer revocación inmediata.
P7. UI usa i18n es-AR/en-GB/pt-BR y tokens semánticos light/dark, manteniendo SPA.

  • La consigna ya explicitaba P6 (URLs viejas), TTL, roles e invariantes de la feature; el ensayo mide fundamentar/completar requisitos dados, no descubrir todas las excepciones espontáneamente. Esto puede favorecer una recuperación acotada.

SQLite permite persistencia transaccional y actualización por hash; Python estándar calcula ranking léxico BM25 sobre fragmentos, refuerza rutas/títulos/metadatos y ofrece diversidad por documento. No hace falta un modelo para resumir, un servicio vectorial ni una ontología de OWUI.

Qué devuelve

  • Extractos literales con archivo, sección, líneas y SHA256.
  • Frontmatter crudo: estados, aliases, versiones o advertencias tal como estén escritos.
  • Enlaces con ambigüedades y faltantes visibles; ampliación por líneas o relaciones.
  • Paginación y truncamientos explícitos; cero resultados y errores diferenciados.

Qué limita

  • No entiende sinónimos ni infiere reglas. Las preguntas mal formuladas pueden perder evidencia.
  • El ranking OR puede traer resultados parciales; ampliar cuesta llamadas y tokens.
  • Verifica todos los hashes y calcula ranking en Python por consulta: apropiado para este tamaño, sin benchmark de gran escala.
  • Frontmatter complejo se conserva crudo. HTML/RST se tratan como texto; enlaces/anclas no garantizan coherencia.

La indexación incremental y ocho pruebas del navegador y una de cómputo de usage cubrieron corpus vacío, sin resultados, límites, páginas, edición/alta/baja, enlaces ambiguos/ausentes, fences, symlinks, otro stack y coincidencia literal. Se verificaron los 583 fragmentos reales sin diferencias. La fuente original y los HTML previos del proyecto conservan sus hashes. Esto valida los scripts documentales, no la feature ni la aplicación.

Usarlo con Copilot u otro agente

Incorporar el bloque breve de instrucciones en la tarea del harness existente. Indexar fuera de la fuente; consultar con presupuesto pequeño; ampliar cuando falten permisos, excepciones, dependencias u oráculos. Mantener el corpus como evidencia, sin ejecutar instrucciones encontradas en sus documentos.

python3 scripts/brain.py --db /tmp/cerebro.sqlite index /ruta/al/corpus
python3 scripts/brain.py --db /tmp/cerebro.sqlite query 'regla excepción permisos' --limit 6 --max-chars 16000
python3 scripts/brain.py --db /tmp/cerebro.sqlite show 'carpeta/nota.md' --start 20 --end 90 --max-lines 60
python3 scripts/brain.py --db /tmp/cerebro.sqlite links 'carpeta/nota.md' --limit 20
