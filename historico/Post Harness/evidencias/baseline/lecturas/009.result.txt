10: # MOC — Almacenamiento
11: 
12: El almacenamiento de archivos sigue un flujo híbrido: primero local, luego migrado a [[MinIO S3]]. El acceso siempre se hace con [[URLs firmadas MinIO|URLs firmadas]].
13: 
14: ## Notas de este cluster
15: 
16: - [[Sistema híbrido de almacenamiento]] — Visión general del flujo local → MinIO y cómo coexisten los dos providers
17: - [[Flujo de subida de archivos]] — Ciclo completo: recepción → guardado local → scheduler → MinIO
18: - [[URLs firmadas MinIO]] — Cómo se generan presigned URLs para acceso seguro temporal
19: - [[Scheduler de limpieza]] — Job diario que elimina archivos huérfanos y vencidos (`FILE_STORAGE_CLEANUP_DAYS`)
20: - [[Borrado en cascada de archivos]] — Al eliminar un chat se eliminan sus archivos en MinIO automáticamente
21: - [[Storage Dashboard]] — Endpoint `/api/v1/storage/status`; métricas de uso para administradores

10: # MOC — Autenticación y Permisos
11: 
12: Todo acceso al sistema pasa por [[Azure AD login exclusivo]]. Los [[Roles de usuario]] y [[Grupos y permisos]] determinan qué puede hacer cada usuario dentro de la aplicación.
13: 
14: ## Notas de este cluster
15: 
16: - [[Azure AD login exclusivo]] — Solo OAuth Azure AD; registro local y formulario de usuario deshabilitados
17: - [[Roles de usuario]] — Los tres roles: `admin`, `user`, `pending`; qué puede hacer cada uno
18: - [[Grupos y permisos]] — Modelo de grupos con JSON de permisos granulares; acceso por grupo o usuario
19: - [[JWT y sesiones]] — Generación y validación de tokens HS256; `WEBUI_SECRET_KEY`
20: - [[bcrypt para contraseñas]] — Por qué se migró de passlib a bcrypt nativo; problema de truncación UTF-8
21: - [[Control de acceso a recursos]] — Campo `access_control` en Knowledge y Files; modos public/private/custom
22:

11: 
12: El ciclo de vida de versiones pasa por 4 pipelines de Azure DevOps (DEV → VALIDACION → PROD → RELEASE). El runtime es [[OpenShift]] con imágenes construidas en Docker.

14: ## Notas de este cluster
15: 
16: - [[Pipelines Azure DevOps]] — Los 4 pipelines y sus responsabilidades: DEV, VALIDACION, PROD, RELEASE
17: - [[Dockerfile]] — CPU-only PyTorch; sin Pyodide; workarounds de SSL corporativo
18: - [[Build frontend]] — Diferencia entre `npm run build` (con Pyodide) y `npm run build:docker` (sin Pyodide, para CI)
19: - [[SSL corporativo en build]] — Por qué `NODE_TLS_REJECT_UNAUTHORIZED=0` está en el Dockerfile y qué riesgo implica
20: - [[Despliegue en OpenShift]] — ConfigMap, Routes, timeout de HAProxy, creación del bucket MinIO
