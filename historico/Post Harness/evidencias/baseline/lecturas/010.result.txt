10: # MOC — Diseño y Frontend
11: 
12: El diseño visual está gobernado por el [[ECO Design System]], basado en Material Design 3. Teal (`#06ABB9`) es el color primario COELSA; Pink es solo acento decorativo. El frontend es una [[SvelteKit 2|SPA en SvelteKit 2]] con SSR deshabilitado.
13: 
14: ## Notas de este cluster
15: 
16: ### Sistema de diseño
17: - [[ECO Design System]] — Overview del sistema basado en Material Design 3; principios y archivos canónicos
18: - [[Tokens primitivos de color]] — Escalas inmutables Teal, Pink, Neutral (0→100) usadas para definir roles
19: - [[Roles semánticos de color]] — `primary`, `secondary`, `tertiary`, `surface` y sus pares `on-*`; cambian entre temas
20: - [[Surface Containers]] — Los 5 niveles de jerarquía visual (lowest → highest) para profundidad sin opacidad
21: - [[Tipografía Saira]] — Fuente corporativa Saira; clases tipográficas de `app.css`
22: - [[Dark mode reglas]] — Cómo se invierten roles (no escalas primitivas) al cambiar de tema
23: 
24: ### Componentes y patrones
25: - [[Patrones de componentes Svelte]] — Guarda chatId; AbortController; unsubscribers en onDestroy; bloques reactivos unificados
26: - [[Manejo de errores frontend]] — `NetworkError`, `TimeoutError`, `GenericError`, `ErrorBoundary`; routing en `+error.svelte`
27: - [[Internacionalización i18n]] — es-AR principal; en-GB y pt-BR disponibles; idiomas eliminados

11: 
12: El sistema soporta dos vías de acceso a modelos: [[Ollama]] nativo y [[LiteLLM proxy]] como proxy OpenAI-compatible. El campo `urlIdx` distingue cuál usar. El tool calling se implementa via [[MCP y tool calling|MCP]] con JSON prompt para modelos sin function calling nativo.
13: 
14: ## Notas de este cluster
15: 
16: - [[Routing de modelos IA]] — Lógica de selección de endpoint; cuándo va a Ollama y cuándo al proxy
17: - [[Validación de urlIdx]] — Fix clave: por qué `urlIdx` determina el routing y no solo `owned_by`
18: - [[MCP y tool calling]] — Non-native function calling con JSON prompt; `json.JSONDecoder().raw_decode()`
19: - [[Cadena SearXNG Context Forge]] — Cadena completa: Open WebUI → MCPO → Context Forge → searxng-mcp → SearXNG
20: - [[SharePoint OneDrive integración]] — Microsoft File Picker v8; permisos `Files.Read.All`; requisitos de CSP
21: - [[PyTorch CPU-only]] — Por qué se usa la variante CPU-only (~200MB vs ~2GB CUDA); impacto en imagen Docker
