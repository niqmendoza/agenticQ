0010 # Flujo de subida de archivos
0011
0012 ## Qué es
0013
0014 Describe el ciclo completo desde que un usuario sube un archivo hasta que queda accesible via URL firmada en MinIO.
0015
0016 ## Pasos del flujo
0017
0018 ### 1. Recepción (router `files.py`)
0019 El endpoint `POST /api/v1/files/` recibe el archivo multipart. El backend:
0020 - Sanitiza el nombre del archivo (protección contra [[Path Traversal]])
0021 - Guarda temporalmente en `data/uploads/<uuid>-<filename>`
0022 - Crea un registro en la tabla `file` con `path` = ruta local
0023
0024 ### 2. Procesamiento RAG (opcional)
0025 Si el archivo va a ser embedido (Knowledge base, búsqueda vectorial):
0026 - Se procesa con los loaders del [[Módulo de retrieval]]
0027 - Los chunks se insertan en [[Milvus]] bajo la colección correspondiente
0028
0029 ### 3. Migración a MinIO (scheduler diario)
0030 El [[Scheduler de limpieza|scheduler]] ejecuta diariamente:
0031 - Lee los registros de `file` con `path` local
0032 - Sube cada archivo a [[MinIO S3]]
0033 - Actualiza el campo `path` en BD con la clave S3
0034 - Genera una [[URLs firmadas MinIO|URL firmada]] para el acceso
0035
0036 ### 4. Acceso
0037 Al solicitar un archivo, el backend:
0038 - Verifica [[Control de acceso a recursos|access_control]]
0039 - Si el path es S3: genera una URL firmada con expiración configurable
0040 - Si el path es local: sirve el archivo directamente
