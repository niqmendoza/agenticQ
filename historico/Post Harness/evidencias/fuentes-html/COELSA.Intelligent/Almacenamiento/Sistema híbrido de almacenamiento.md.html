0009
0010 # Sistema híbrido de almacenamiento
0011
0012 ## Qué es
0013
0014 El almacenamiento de archivos en COELSA.Intelligent opera en modo **híbrido**: los archivos se reciben localmente y luego se migran a [[MinIO S3]]. Los archivos viejos y los nuevos coexisten hasta que el scheduler los migra.
0015
0016 ## Flujo completo
0017
0018 ```
0019 Usuario sube archivo
0020 ↓
0021 Backend guarda en data/uploads/ (local temporal)
0022 ↓
0023 [Scheduler diario] detecta archivos locales
0024 ↓
0025 Migra a MinIO → genera presigned URL
0026 ↓
0027 Actualiza metadatos en BD (path = s3://bucket/key)
0028 ↓
0029 [Acceso futuro] devuelve URL firmada de MinIO
0030 ```
0031
0032 ## Proveedores disponibles
0033
0034 La interfaz `StorageProvider` (en `backend/server/storage/provider.py`) es abstracta. Las implementaciones concretas son:
0035 - `LocalStorageProvider` — guarda en `data/uploads/`
0036 - `S3StorageProvider` (MinIO / AWS S3)
0037 - `GCSStorageProvider` (Google Cloud Storage)
0038 - `AzureBlobStorageProvider` (Azure Blob Storage)
0039
0040 La variable `STORAGE_PROVIDER` en `.env` selecciona el provider activo.
0041
0042 ## Fallback local
0043
0044 Si MinIO no está disponible, el sistema usa el almacenamiento local. Esto permite desarrollo local sin configurar MinIO, aunque los archivos no persisten en caso de recreación del contenedor.
0045
0046 ## Script de migración
0047
0048 Para migrar archivos existentes a MinIO en un entorno ya en producción:
0049
0050 ```bash
0051 python scripts/migrate_to_minio.py
0052 ```
