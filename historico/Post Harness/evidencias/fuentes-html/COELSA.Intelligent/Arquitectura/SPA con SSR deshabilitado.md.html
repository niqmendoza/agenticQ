0010 # SPA con SSR deshabilitado
0011
0012 ## Qué es
0013
0014 COELSA.Intelligent tiene el SSR (Server-Side Rendering) de [[SvelteKit 2]] **explícitamente deshabilitado**:
0015
0016 ```javascript
0017 // src/routes/+layout.js
0018 export const ssr = false;
0019 ```
0020
0021 Esto convierte la aplicación en una **SPA pura**: el servidor solo sirve el HTML inicial y los assets; toda la lógica de renderizado corre en el navegador del cliente.
0022
0023 ## Por qué está deshabilitado
0024
0025 Dos razones principales:
0026
0027 1. **Modelo de despliegue**: COELSA.Intelligent usa un backend FastAPI separado en otro proceso/contenedor. El SSR de SvelteKit requeriría que el propio servidor Node.js hiciera llamadas al backend durante el renderizado, complicando el modelo de despliegue en [[OpenShift]].
0028
0029 2. **Seguridad (CVE-2025-7969)**: La vulnerabilidad XSS de `markdown-it` afecta únicamente contextos SSR. Al tener SSR deshabilitado, este vector de ataque no existe. Ver [[CVE-2025-7969 markdown-it]].
0030
0031 ## Implicaciones
0032
0033 - La app **no funciona sin JavaScript** en el cliente. No es un trade-off relevante para el caso de uso (chat corporativo interno).
0034 - Los [[CSP con nonces|nonces CSP]] **no son compatibles** con el modo de desarrollo de SvelteKit (`npm run dev`), que genera scripts dinámicamente en el navegador. Los nonces solo se activan en OpenShift (`ENABLE_CSP_NONCES=true`).
0035 - El build produce assets estáticos que se sirven desde el backend FastAPI como archivos estáticos.
0036
