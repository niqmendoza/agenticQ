0009
0010 # Control de acceso a recursos
0011
0012 ## Qué es
0013
0014 Los modelos `Knowledge` y `File` tienen un campo `access_control` en formato JSON que define quién puede leer y escribir ese recurso. El campo `None` significa acceso público para todos los `user`.
0015
0016 ## Modos de acceso
0017
0018 | Valor de `access_control` | Significado |
0019 |--------------------------|-------------|
0020 | `None` | Acceso público — cualquier usuario con rol `user` puede leer |
0021 | `{}` (objeto vacío) | Acceso privado — solo el propietario puede acceder |
0022 | Objeto con reglas | Acceso custom — según grupos y usuarios específicos |
0023
0024 ## Estructura del objeto custom
0025
0026 ```json
0027 {
0028 "read": {
0029 "group_ids": ["grupo-id-1", "grupo-id-2"],
0030 "user_ids": ["user-id-1"]
0031 },
0032 "write": {
0033 "group_ids": [],
0034 "user_ids": ["user-id-admin"]
0035 }
0036 }
0037 ```
0038
0039 ## Evaluación de acceso
0040
0041 La función `has_access()` en `backend/server/utils/access_control.py` evalúa si un usuario tiene permiso sobre un recurso. La evaluación verifica:
0042 1. Si el usuario es el propietario → acceso total
0043 2. Si el usuario tiene rol `admin` → acceso total
0044 3. Si el `access_control` es `None` → acceso de lectura para `user`
0045 4. Si hay reglas custom → verifica `group_ids` y `user_ids`
