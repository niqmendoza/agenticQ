0010 # bcrypt para contraseñas
0011
0012 ## Qué es
0013
0014 COELSA.Intelligent usa la librería **`bcrypt`** nativa de Python para el hashing de contraseñas, en lugar de `passlib.CryptContext` que usaba el upstream.
0015
0016 ```python
0017 # backend/server/utils/auth.py
0018 import bcrypt
0019
0020 def verify_password(plain_password, hashed_password):
0021 return bcrypt.checkpw(
0022 plain_password.encode('utf-8'),
0023 hashed_password.encode('utf-8')
0024 )
0025 ```
0026
0027 ## Por qué se migró de passlib
0028
0029 `passlib.CryptContext` no manejaba correctamente el **límite de 72 bytes de bcrypt** en la codificación UTF-8 interna. El problema se manifestaba al crear usuarios incluso con contraseñas cortas — el error aparecía por cómo `passlib` gestionaba internamente la codificación, no por la longitud de la contraseña.
0030
0031 El reemplazo por `bcrypt` nativo resuelve esto porque:
0032 1. Maneja explícitamente la codificación `utf-8` al llamar a `encode()`
0033 2. No tiene la capa de abstracción de `passlib` que introducía el bug
0034
0035 ## Contexto
0036
0037 Aunque COELSA.Intelligent tiene el login local deshabilitado (ver [[Azure AD login exclusivo]]), el código de autenticación por contraseña sigue existente en el backend para usos internos (API keys, etc.) y como fallback en caso de que el login local se rehabilite en el futuro.
