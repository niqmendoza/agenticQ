0010 # MOC — Modelos IA y Routing
0011
0012 El sistema soporta dos vías de acceso a modelos: [[Ollama]] nativo y [[LiteLLM proxy]] como proxy OpenAI-compatible. El campo `urlIdx` distingue cuál usar. El tool calling se implementa via [[MCP y tool calling|MCP]] con JSON prompt para modelos sin function calling nativo.
0013
0014 ## Notas de este cluster
0015
0016 - [[Routing de modelos IA]] — Lógica de selección de endpoint; cuándo va a Ollama y cuándo al proxy
0017 - [[Validación de urlIdx]] — Fix clave: por qué `urlIdx` determina el routing y no solo `owned_by`
0018 - [[MCP y tool calling]] — Non-native function calling con JSON prompt; `json.JSONDecoder().raw_decode()`
0019 - [[Cadena SearXNG Context Forge]] — Cadena completa: Open WebUI → MCPO → Context Forge → searxng-mcp → SearXNG
0020 - [[SharePoint OneDrive integración]] — Microsoft File Picker v8; permisos `Files.Read.All`; requisitos de CSP
0021 - [[PyTorch CPU-only]] — Por qué se usa la variante CPU-only (~200MB vs ~2GB CUDA); impacto en imagen Docker
