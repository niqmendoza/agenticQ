0009
0010 # Routing de modelos IA
0011
0012 ## Qué es
0013
0014 Cuando un usuario envía un mensaje, el backend debe decidir a qué endpoint enviar la request de inferencia. COELSA.Intelligent soporta dos destinos:
0015 - **[[Ollama]]** nativo — endpoint Ollama en `OLLAMA_BASE_URL`
0016 - **[[LiteLLM proxy]]** — proxy OpenAI-compatible en `OPENAI_API_BASE_URL`
0017
0018 ## Lógica de routing
0019
0020 ```
0021 backend/server/utils/chat.py (líneas ~263–293)
0022 ```
0023
0024 El routing evalúa en orden:
0025
0026 1. **¿Tiene `urlIdx`?** → Si está definido, el modelo es proxied → usar endpoint OpenAI (LiteLLM)
0027 2. **¿`owned_by` == "ollama"?** → Usar endpoint nativo de Ollama
0028 3. **Default** → Usar endpoint OpenAI (LiteLLM)
0029
0030 ## Por qué `urlIdx` tiene prioridad
0031
0032 El campo `owned_by` no es suficiente para determinar el endpoint correcto. Los modelos con prefijo `ollama/` en LiteLLM tienen `owned_by=ollama` pero **deben** ir al proxy, no al endpoint nativo de Ollama. Si van al endpoint nativo, LiteLLM no puede procesar la respuesta y la UI muestra respuestas vacías.
0033
0034 Ver [[Validación de urlIdx]] para el detalle del bug y la corrección.
0035
0036 ## Formatos de respuesta
0037
0038 | Endpoint | Formato de respuesta |
0039 |----------|---------------------|
0040 | Ollama nativo | Formato Ollama propio |
0041 | LiteLLM proxy | Formato OpenAI estándar (siempre) |
