0010 # Azure AD OAuth
0011
0012 ## Qué es
0013
0014 COELSA.Intelligent usa **Azure Active Directory** como único proveedor de identidad, implementado mediante el protocolo **OAuth 2.0 / OpenID Connect**. El registro local de usuarios y el formulario de login con usuario/contraseña están deshabilitados. Ver [[Azure AD login exclusivo]].
0015
0016 ## Variables de entorno requeridas
0017
0018 ```env
0019 OAUTH_CLIENT_ID=<azure-client-id>
0020 OAUTH_CLIENT_SECRET=<azure-client-secret>
0021 OAUTH_PROVIDER_NAME=microsoft
0022 OPENID_PROVIDER_URL=https://login.microsoftonline.com/<tenant-id>/v2.0/.well-known/openid-configuration
0023 ```
0024
0025 ## Flujo de autenticación
0026
0027 1. El usuario hace clic en "Login con Microsoft".
0028 2. Es redirigido a `login.microsoftonline.com` para autenticarse.
0029 3. Azure AD devuelve un código de autorización al callback del backend.
0030 4. El backend intercambia el código por tokens (access + id token).
0031 5. El `sub` del id token se guarda como `oauth_sub` en el modelo `User`.
0032 6. Se genera un JWT interno (ver [[JWT y sesiones]]) que el frontend usa en todas las requests.
0033
0034 ## Para SharePoint / OneDrive
0035
0036 La misma App Registration de Azure AD puede usarse para el [[SharePoint OneDrive integración|File Picker de SharePoint]], pero requiere el permiso adicional `Files.Read.All`.
0037
0038 ## CSP
0039
0040 El dominio `login.microsoftonline.com` debe estar incluido en la CSP del Route de OpenShift para que el redirect funcione. Ver [[CSP con nonces]] y [[Despliegue en OpenShift]].
