0010 # LiteLLM proxy
0011
0012 ## Qué es
0013
0014 **LiteLLM** es un proxy OpenAI-compatible que unifica el acceso a múltiples proveedores de modelos (OpenAI, Azure OpenAI, Anthropic, Ollama, etc.) bajo una única API estándar. COELSA.Intelligent lo usa para acceder a modelos que no están en Ollama nativo.
0015
0016 ## Configuración
0017
0018 ```env
0019 OPENAI_API_BASE_URL=http://litellm:4000/v1
0020 OPENAI_API_KEY=sk-...
0021 ```
0022
0023 ## El problema de routing (resuelto)
0024
0025 Los modelos con prefijo `ollama/` en LiteLLM tienen `owned_by=ollama`. El upstream de Open WebUI usaba solo `owned_by` para decidir el endpoint, y los enviaba incorrectamente al endpoint nativo de Ollama. LiteLLM siempre responde en **formato OpenAI**, no en formato Ollama nativo, lo que generaba **respuestas vacías en la UI**.
0026
0027 La corrección valida también el campo `urlIdx`: si está presente, el modelo es proxied y debe usar el endpoint OpenAI (LiteLLM), independientemente del valor de `owned_by`.
0028
0029 Ver [[Validación de urlIdx]] para el detalle técnico.
0030
0031 ## Modelo con non-native function calling
0032
0033 El modelo `gpt-oss:120b` usa JSON prompt en lugar de function calling nativo porque no soporta tool calling de forma confiable. Ver [[MCP y tool calling]].
