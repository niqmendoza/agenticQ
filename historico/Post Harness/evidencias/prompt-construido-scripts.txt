## Feature mock: renovar acceso temporal a un archivo desde el chat
Es una extensión propuesta; no afirmar que existe.
P1. Usuario activo solicita renovar acceso de lectura a un File por ID desde el chat. Backend valida identidad y permisos actuales antes de resolver el path; pending no puede usarlo. No aceptar URL/ruta arbitraria del cliente.
P2. Para path S3 emitir acceso firmado al objeto específico. TTL opcional entero en segundos: 60 ≤ TTL ≤ 3600; default 3600. Rechazar fuera de rango, fracciones, booleanos y texto con 422. Son límites y política de validación propuestos, no contratos existentes.
P3. Para path local devolver referencia de descarga del backend protegido; no fingir URL S3 ni prometer expiración S3. No promover el archivo a MinIO desde esta acción.
P4. No alterar ACL, contenido, chat_id ni disparar borrado, limpieza o embeddings; política de last_accessed_at al renovar ABIERTA hasta decisión de producto.
P5. UI con acción explícita, carga y reintento; impedir que una respuesta de otro chat reemplace la actual. Errores sin detalles internos en producción.
P6. Informar que URLs S3 emitidas previamente pueden seguir funcionando hasta expirar aunque se revoque el permiso. No prometer revocación inmediata.
P7. UI usa i18n es-AR/en-GB/pt-BR y tokens semánticos light/dark, manteniendo SPA.

El servidor firma la URL con las credenciales S3 y establece un tiempo de expiración.\n\n## Cómo funciona\n\n```python\n# Pseudocódigo de generación (StorageProvider.get_presigned_url)\nurl = s3_client.generate_presigned_url(\n    'get_object',\n    Params={'Bucket': S3_BUCKET_NAME, 'Key': file_path},\n    ExpiresIn=3600  # 1 hora por defecto\n)\n```\n\nLa URL resultante incluye la firma criptográfica y la fecha de expiración en los query params. Solo es válida hasta esa fecha y solo para el objeto específico.\n\n## Por qué URLs firmadas\n\n- **Seguridad**: el cliente nunca recibe credenciales del bucket; solo puede acceder al archivo específico por el tiempo configurado\n- **Control de acceso**: si el [[Control de acceso a recursos|access_control]] del archivo cambia, las URLs viejas siguen siendo válidas hasta su expiración pero no se generan nuevas\n- **Descarga directa**: el cliente descarga directo de MinIO sin pasar por el backend, reduciendo la carga del servidor\n\n## Configuración de expiración\n\nLa expiración por defecto es **3600 segundos (1 hora)**. El parámetro `ExpiresIn` es configurable en la llamada a `get_presigned_url()`.\n\n## Timeouts boto3 (Windows)\n\nPara evitar timeouts en entornos Windows con latencia de red:\n- Connect timeout: 30s\n- Read timeout: 120s\n- 10 reintentos con backoff exponencial\n- TCP keepalive habilitado\n\n## Relacionado\n\n- [[MinIO S3]] — El proveedor que genera estas URLs\n- [[Flujo de subida de archivos]] — Cuándo se genera la URL firmada en el ciclo de vida del archivo\n- [[Sistema híbrido de almacenamiento]] — El contexto general del sistema de almacenamiento\n- [[MOC - Almacenamiento]] — Índice del cluster de almacenamiento",
